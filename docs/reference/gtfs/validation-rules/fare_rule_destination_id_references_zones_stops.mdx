## Propriedades da regra

| Propriedade | Valor |
|---|---|
| Rule ID | `fare_rule_destination_id_references_zones_stops` |
| Ficheiros | `fare_rules.txt`, `stops.txt` |
| Campo | `destination_id` |
| Tipo | Identificador externo |
| Severidade | Opcional |

**Descrição do campo:** identifica uma zona de destino. Quando uma classe tarifária aceita vários destinos, deve existir uma linha em `fare_rules.txt` para cada `destination_id`.

Mais informação em [fare_rules.txt](/reference/gtfs/schedule/fare_rules) e [stops.txt](/reference/gtfs/schedule/stops).

## Como funciona

Quando a regra passa, `destination_id` está vazio quando permitido ou coincide com um identificador indexado de `stops.txt`. A referência prevista é `zone_id`, mas a pesquisa atual também aceita valores presentes apenas em `stop_id` ou `stop_code`. A regra **não verifica se a zona contém paragens usadas pelo itinerário**.

A regra avalia cada linha do `fare_rules.txt`, seguindo os passos abaixo por ordem, até um deles dar o resultado.

| # | Pergunta | Se sim | Se não |
|---|---|---|---|
| 1 | O campo está vazio? | Verifica se a configuração da regra exige ou recomenda este campo. Se sim, reporta o problema. Se não, aceita | Segue para o passo 2 |
| 2 | A configuração da regra define que este campo **não deve ser preenchido**? | ❌ Reporta o problema | Segue para o passo 3 |
| 3 | O valor coincide com um identificador indexado de `stops.txt`? | ✅ Passa | ❌ Reporta o problema: zona inexistente |

O valor é comparado tal como foi escrito. Os espaços e as maiúsculas não são normalizados. Uma linha com todos os campos vazios é ignorada antes desta regra.

## Como se relacionam

No modelo GTFS, `destination_id` deve coincidir com um `zone_id` de `stops.txt`. A validação atual pesquisa em conjunto os valores de `stop_id`, `zone_id` e `stop_code`.

## Exemplos

| `destination_id` em `fare_rules.txt` | Identificadores em `stops.txt` | Resultado | Porquê |
|---|---|---|---|
| `Z2` | `zone_id` = `Z2` | ✅ Passa | Zona existente |
| campo vazio | `zone_id` = `Z2` | ✅ Passa | Campo opcional |
| `Z9` | `zone_id` = `Z2` | ❌ Problema | Identificador inexistente |
| `S2` | apenas `stop_id` = `S2` | ✅ Passa | A pesquisa atual junta os identificadores |
| `Z2` quando o campo é proibido | `zone_id` = `Z2` | ❌ Problema | Campo preenchido indevidamente |

## Como corrigir

| Problema | Causa provável | O que fazer |
|---|---|---|
| Zona inexistente | O valor não corresponde a nenhum identificador indexado de `stops.txt` | Corrigir `destination_id` em `fare_rules.txt` para um `zone_id` existente em `stops.txt` |
| Campo em falta | A configuração da regra exige ou recomenda este campo | Preencher `destination_id` em `fare_rules.txt` com um `zone_id` existente em `stops.txt` |
| Campo preenchido quando não devia | A configuração da regra define que este campo não deve ter valor | Remover o valor de `destination_id` em `fare_rules.txt` |
