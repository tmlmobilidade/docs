## Propriedades da regra

| Propriedade | Valor |
|---|---|
| Rule ID | `vehicle_model_required` |
| Ficheiro | `vehicles.txt` |
| Campo | `model` |
| Tipo | Texto |
| Severidade | Obrigatório |

**Descrição do campo:** modelo do veículo.

Mais informação em [vehicles.txt](/reference/gtfs/schedule/vehicles).

## Como funciona

O campo `model` tem de estar preenchido quando a configuração da regra o exige ou recomenda. A regra não verifica a grafia, a relação com a marca nem uma lista de modelos permitidos.

A regra avalia cada linha do `vehicles.txt`, seguindo os passos abaixo por ordem, até um deles dar o resultado.

| # | Pergunta | Se sim | Se não |
|---|---|---|---|
| 1 | O campo está vazio? | Verifica se a configuração da regra exige ou recomenda este campo. Se sim, reporta o problema. Se não, aceita | Segue para o passo 2 |
| 2 | A configuração da regra define que este campo **não deve ser preenchido**? | ❌ Reporta o problema | ✅ Passa |

## Exemplos

| Valor | Resultado | Porquê |
|---|---|---|
| `Citaro` | ✅ Passa | Campo preenchido |
| campo vazio | ❌ Problema | Campo obrigatório |
| `7900 Electric` quando o campo é proibido | ❌ Problema | Campo preenchido indevidamente |

## Como corrigir

| Problema | Causa provável | O que fazer |
|---|---|---|
| Campo em falta | A configuração da regra exige ou recomenda `model` | Preencher `model` em `vehicles.txt` com o modelo do veículo |
| Campo preenchido quando não devia | A configuração da regra proíbe `model` | Remover o valor de `model` em `vehicles.txt` |
