## Propriedades da regra

| Propriedade | Valor |
|---|---|
| Rule ID | `calendar_start_end_dates_valid` |
| Ficheiro | `calendar.txt` |
| Campos | `start_date`, `end_date` |
| Tipo | Data |
| Severidade | Obrigatório |

**Descrição dos campos:**

- `start_date`: primeiro dia do intervalo de funcionamento do serviço.
- `end_date`: último dia do intervalo de funcionamento do serviço, incluído nesse intervalo.

Mais informação em [calendar.txt](/reference/gtfs/schedule/calendar).

## Como funciona

Verifica se `start_date` é anterior a `end_date` em `calendar.txt`. A regra compara os textos; não confirma se as datas existem ou se estão no formato correto.

A regra avalia cada linha do `calendar.txt`, seguindo os passos abaixo por ordem, até um deles dar o resultado.

| # | Pergunta | Se sim | Se não |
|---|---|---|---|
| 1 | A configuração da regra está desativada? | A verificação não é executada | Segue para o passo 2 |
| 2 | Falta uma das duas datas? | Não compara as datas nesta linha | Segue para o passo 3 |
| 3 | A data inicial é igual ou posterior à data final? | ❌ Reporta o problema: intervalo inválido | ✅ Passa |

Os espaços não são removidos. A comparação só representa a ordem cronológica quando ambas as datas usam `AAAAMMDD`.

## Como se relacionam

`end_date` tem de ser posterior a `start_date`. Datas iguais não são aceites.

## Exemplos

| `start_date` | `end_date` | Resultado | Porquê |
|---|---|---|---|
| `20240101` | `20240201` | ✅ Passa | Data inicial anterior |
| `20240201` | `20240101` | ❌ Problema | Datas invertidas |
| `20240101` | `20240101` | ❌ Problema | Datas iguais |

## Como corrigir

| Problema | Causa provável | O que fazer |
|---|---|---|
| Intervalo inválido | A data inicial é igual ou posterior à data final | Definir uma data posterior a `start_date` em `end_date` em `calendar.txt`. |
