title: Data da exceção de serviço
description: Verifica se a data de uma exceção em calendar_dates.txt representa uma data válida no formato AAAAMMDD.
---

## Propriedades da regra

| Propriedade | Valor |
|---|---|
| Rule ID | `calendar_dates_exception_date_valid_yyyymmdd` |
| Ficheiro | `calendar_dates.txt` |
| Campo | `date` |
| Tipo | Data |
| Severidade | Obrigatório |

**Descrição do campo:** data em que ocorre a exceção de serviço.

Mais informação em [calendar_dates.txt](/reference/gtfs/schedule/calendar_dates).

## Como funciona

Quando a regra recebe um valor, este tem de representar uma data real no formato AAAAMMDD. A implementação atual deixa passar um campo vazio porque não aplica a configuração de severidade nesta verificação. A regra **não verifica o serviço nem o tipo de exceção associados à data**.

A regra avalia cada linha do `calendar_dates.txt`, seguindo os passos abaixo por ordem, até um deles dar o resultado.

| # | Pergunta | Se sim | Se não |
|---|---|---|---|
| 1 | O campo está vazio? | ✅ Passa sem reportar um problema | Segue para o passo 2 |
| 2 | A verificação considera o campo proibido? | ❌ Reporta o problema | Segue para o passo 3 |
| 3 | O valor tem oito algarismos e representa uma data real? | ✅ Passa | ❌ Reporta o problema: data inválida |

Os espaços não são removidos. O formato aceite é exatamente AAAAMMDD. Na execução atual, a configuração da regra não chega ao passo 2.

## Exemplos

| Valor | Resultado | Porquê |
|---|---|---|
| `20240101` | ✅ Passa | Data válida |
| campo vazio | ✅ Passa | O vazio é atualmente ignorado |
| `2024-01-01` | ❌ Problema | Formato incorreto |
| `20240230` | ❌ Problema | Dia inexistente |

## Como corrigir

| Problema | Causa provável | O que fazer |
|---|---|---|
| Data inválida | O valor não tem oito algarismos ou não representa uma data real | Corrigir `date` em `calendar_dates.txt` para uma data válida no formato AAAAMMDD |
