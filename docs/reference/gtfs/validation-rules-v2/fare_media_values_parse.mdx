title: Valor numérico do tipo de meio de pagamento

## Propriedades da regra

| Propriedade | Valor |
|---|---|
| Rule ID | `fare_media_values_parse` |
| Ficheiro | `fare_media.txt` |
| Campo | `fare_media_type` |
| Tipo | Enumeração (`0` a `4`) |
| Severidade | Obrigatório |

**Descrição do campo:** tipo de meio de pagamento. Os valores são `0` (nenhum), `1` (bilhete de papel), `2` (cartão de transporte), `3` (cEMV) e `4` (aplicação móvel).

Mais informação em [fare_media.txt](/reference/gtfs/schedule/fare_media).

## Como funciona

O `fare_media_type` tem de ser escrito como número inteiro. Se não for, a linha inteira deixa de ser avaliada pelas outras regras do `fare_media.txt`. A regra **não verifica se o número é um tipo válido**, como `0` a `4`. Isso é verificado por outra regra.

A regra avalia cada linha do `fare_media.txt`, seguindo o passo abaixo, que dá o resultado.

| # | Pergunta | Se sim | Se não |
|---|---|---|---|
| 1 | O `fare_media_type` tem um valor que não se lê como número inteiro? | ❌ Reporta o problema. A linha deixa de ser avaliada pelas outras regras | ✅ Passa |

Um campo vazio não é um problema nesta regra. Os campos `fare_media_id` e `fare_media_name` são texto e aceitam qualquer valor.

## Exemplos

| Valor de `fare_media_type` | Resultado | Porquê |
|---|---|---|
| `2` | ✅ Passa | Número inteiro |
| `9` | ✅ Passa | É um número inteiro, mesmo fora de `0` a `4` |
| `2.5` | ❌ Problema | Tem casas decimais |
| `cartao` | ❌ Problema | Texto em vez de número |

## Como corrigir

| Problema | Causa provável | O que fazer |
|---|---|---|
| Valor inválido em `fare_media_type` | O valor tem texto ou casas decimais | Em `fare_media.txt`, escrever o `fare_media_type` como número inteiro de `0` a `4` |
