---
title: Formato numérico dos campos de trips.txt
description: Verifica se os campos direction_id, wheelchair_accessible e bikes_allowed de trips.txt, quando preenchidos, representam números inteiros válidos.
---

## Propriedades da regra

| Propriedade | Valor |
|---|---|
| Rule ID | `trips_values_parse` |
| Ficheiro | `trips.txt` |
| Campos | `direction_id`, `wheelchair_accessible`, `bikes_allowed` |
| Tipo | Número inteiro |
| Severidade | Condicional (aplica-se apenas quando o campo tem valor) |

**Descrição dos campos:**

- `direction_id`: código numérico que indica o sentido de circulação da viagem.
- `wheelchair_accessible`: código numérico que indica a acessibilidade da viagem para cadeiras de rodas.
- `bikes_allowed`: código numérico que indica se são permitidas bicicletas na viagem.

Mais informação em [trips.txt](/reference/gtfs/schedule/trips).

## Como funciona

Quando `direction_id`, `wheelchair_accessible` ou `bikes_allowed` têm um valor, esse valor tem de ser um número inteiro, escrito apenas com algarismos e, opcionalmente, um sinal de menos à frente. A regra **não verifica** se o número está dentro do conjunto de códigos válidos de cada campo (por exemplo, `0`, `1` ou `2`) — essa verificação pertence a outras regras. Um campo vazio não é testado por esta regra. Os restantes campos de `trips.txt` são texto e nunca falham este teste.

A regra avalia cada linha do `trips.txt`, seguindo os passos abaixo por ordem, para cada um dos três campos, até um deles dar o resultado.

| # | Pergunta | Se sim | Se não |
|---|---|---|---|
| 1 | O campo está vazio? | ✅ Passa, sem testar o formato | Segue para o passo 2 |
| 2 | O texto representa um número inteiro (por exemplo `1` ou `-2`, sem casas decimais nem letras)? | ✅ Passa | ❌ Reporta o problema: formato inválido |

## Como se relacionam

Os três campos são verificados de forma independente: um problema num deles não altera o resultado dos outros dois. Partilham o mesmo `rule_id` nas mensagens porque falham todos pelo mesmo motivo — o texto não é um número inteiro. Quando um dos três falha nesta linha, a viagem inteira é descartada e as restantes regras de `trips.txt` deixam de se aplicar a essa linha.

## Exemplos

| `direction_id` | `wheelchair_accessible` | `bikes_allowed` | Resultado | Porquê |
|---|---|---|---|---|
| `1` | `2` | `1` | ✅ Passa | Todos os valores são números inteiros válidos |
| (vazio) | (vazio) | (vazio) | ✅ Passa | Campos vazios não são testados por esta regra |
| `um` | `2` | `1` | ❌ Problema | `direction_id` não é um número inteiro |
| `1` | `dois` | `1` | ❌ Problema | `wheelchair_accessible` não é um número inteiro |
| `1` | `2` | `1.5` | ❌ Problema | `bikes_allowed` tem casas decimais, não é um número inteiro |

## Como corrigir

| Problema | Causa provável | O que fazer |
|---|---|---|
| Formato inválido em `direction_id` | O texto de `direction_id` em `trips.txt` não é um número inteiro (por exemplo, tem letras, espaços ou casas decimais) | Substituir o valor de `direction_id` por um número inteiro, por exemplo `0` |
| Formato inválido em `wheelchair_accessible` | O texto de `wheelchair_accessible` em `trips.txt` não é um número inteiro | Substituir o valor de `wheelchair_accessible` por um número inteiro, por exemplo `1` |
| Formato inválido em `bikes_allowed` | O texto de `bikes_allowed` em `trips.txt` não é um número inteiro | Substituir o valor de `bikes_allowed` por um número inteiro, por exemplo `1` |
