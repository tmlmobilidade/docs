## Propriedades da regra

| Propriedade | Valor |
|---|---|
| Rule ID | `fare_rule_contains_id_references_zones_stops` |
| Ficheiros | `fare_rules.txt`, `stops.txt` |
| Campo | `contains_id` |
| Tipo | Identificador externo |
| Severidade | Opcional |

**Descrição do campo:** identifica uma zona que o passageiro atravessa ao usar uma classe tarifária. Alguns sistemas usam estas zonas para determinar a tarifa correta. Todas as zonas indicadas para a classe tarifária têm de fazer parte do itinerário.

Mais informação em [fare_rules.txt](/reference/gtfs/schedule/fare_rules) e [stops.txt](/reference/gtfs/schedule/stops).

## Como funciona

Quando a regra passa, `contains_id` está vazio quando permitido ou coincide com um identificador indexado de `stops.txt`. A referência prevista é `zone_id`, mas a pesquisa atual também aceita valores presentes apenas em `stop_id` ou `stop_code`. A regra **não verifica se o itinerário atravessa realmente a zona**.

A regra avalia cada linha do `fare_rules.txt`, seguindo os passos abaixo por ordem, até um deles dar o resultado.

| # | Pergunta | Se sim | Se não |
|---|---|---|---|
| 1 | O campo está vazio? | Verifica se a configuração da regra exige ou recomenda este campo. Se sim, reporta o problema. Se não, aceita | Segue para o passo 2 |
| 2 | A configuração da regra define que este campo **não deve ser preenchido**? | ❌ Reporta o problema | Segue para o passo 3 |
| 3 | O valor coincide com um identificador indexado de `stops.txt`? | ✅ Passa | ❌ Reporta o problema: zona inexistente |

O valor é comparado tal como foi escrito. Os espaços e as maiúsculas não são normalizados. Uma linha com todos os campos vazios é ignorada antes desta regra.

## Como se relacionam

No modelo GTFS, `contains_id` deve coincidir com um `zone_id` de `stops.txt`. A validação atual pesquisa em conjunto os valores de `stop_id`, `zone_id` e `stop_code`. Para exigir várias zonas, repete-se a classe tarifária numa linha por zona.

## Exemplos

| `contains_id` em `fare_rules.txt` | Identificadores em `stops.txt` | Resultado | Porquê |
|---|---|---|---|
| `Z5` | `zone_id` = `Z5` | ✅ Passa | Zona existente |
| campo vazio | `zone_id` = `Z5` | ✅ Passa | Campo opcional |
| `Z9` | `zone_id` = `Z5` | ❌ Problema | Identificador inexistente |
| `S5` | apenas `stop_id` = `S5` | ✅ Passa | A pesquisa atual junta os identificadores |
| `Z5` quando o campo é proibido | `zone_id` = `Z5` | ❌ Problema | Campo preenchido indevidamente |

## Como corrigir

| Problema | Causa provável | O que fazer |
|---|---|---|
| Zona inexistente | O valor não corresponde a nenhum identificador indexado de `stops.txt` | Corrigir `contains_id` em `fare_rules.txt` para um `zone_id` existente em `stops.txt` |
| Campo em falta | A configuração da regra exige ou recomenda este campo | Preencher `contains_id` em `fare_rules.txt` com um `zone_id` existente em `stops.txt` |
| Campo preenchido quando não devia | A configuração da regra define que este campo não deve ter valor | Remover o valor de `contains_id` em `fare_rules.txt` |
