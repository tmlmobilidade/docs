## Campos que serão validados nesta regra

| Nome do Campo | Tipo                                         | Presença    | Descrição                                                                                                 |
| ------------- | -------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------- |




### O que esta validação faz 

No `stops.txt`, o campo indica se a paragem tem banco e o estado (não aplicável, sem banco, mau estado, bom estado). A validação restringe o valor aos códigos admitidos pela referência, trata o campo vazio conforme o modo de validação (silêncio, obrigatoriedade ou recomendação), recusa o campo quando não deve existir no feed e pode limitar quais códigos são aceites além do mínimo GTFS.

### Passa

- Valor 0, 1, 2 ou 3, conforme a referência do campo.
- Valor dentro do conjunto de códigos permitidos para o feed, quando esse conjunto existe.
- Campo vazio quando o modo de validação não exige mensagem (por exemplo, tratar a ausência como neutra ou não aplicável).
- Campo vazio ou omitido no fluxo em que a presença não é verificada.

### Falha

- Valor inválido: número fora de 0–3. _Correção:_ usar só códigos da documentação GTFS de `has_bench`.
- Proibido: veio valor mas o feed não deve publicar este campo. _Correção:_ remover o valor ou alinhar a política de dados.
- Código não permitido: valor válido na referência mas fora da lista aceite no feed. _Correção:_ escolher um dos códigos admitidos ou rever a lista.
- Ausência com obrigatoriedade ou recomendação registada. _Correção:_ preencher com o código adequado à realidade da paragem ou clarificar se o campo é exigido.
