## Campos que serão validados nesta regra

| `contains_id` | ID estrangeiro que referencia `stops.zone_id` | Opcional | Identifica as zonas pelas quais um passageiro passará quando utiliza uma determinada classe tarifária. Utilizado em alguns sistemas para calcular a classe tarifária correcta. <br/><hr/> <u>Exemplo</u>: Se a classe tarifária "c" estiver associada a todas as viagens na rota GRT que passam pelas zonas 5, 6 e 7, o ficheiro `fare_rules.txt` conterá estas registos:<br/><br/>`fare_id,route_id,...,contains_id`<br/>`c,GRT,...,5`<br/>`c,GRT,...,6`<br/>`c,GRT,...,7`<br/> <br/>Como todas as zonas contains_id devem corresponder para que a tarifa seja aplicada, um itinerário que passe pelas zonas 5 e 6, mas não pela zona 7, não terá a classe tarifária "c". ## O que esta validação faz 

No ficheiro `fare_rules`, o campo `contains_id` identifica zonas pela referência usada no conjunto de dados (no GTFS associa-se a `zone_id` em `stops.txt`). Serve para indicar por que zonas o utente pode circular dentro da mesma classe tarifária. Para uma dada combinação `fare_id` / regra, costuma ser necessário cumprir todas as zonas listadas em linhas com o mesmo critério para essa tarifa se aplicar (exemplo clássico três zonas na regra e o percurso só usar duas não aplica essa classe).

A severidade vem da regra. Se estiver em ignorar, ausência do valor não é reportada. Se estiver em proibido, não deve haver valor (presença ou ausência conforme o ramo proibido descrito abaixo). Entre outros casos, ausência pode ser recomendada ou obrigatória conforme a severidade. Quando há valor, este tem de existir no modelo de dados carregado para paragens (referência cruzada com a tabela de paragens do feed).
