## Regras de validação do campo trip_headsign


### Campos que serão utilizados nesta regra

| Nome do Campo   | Tipo  | Presença    | Descrição                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------- | ----- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `trip_headsign` | Texto | Opcional    | Texto que aparece na sinalização identificando o destino da viagem para os passageiros. <br/>Este campo é recomendado para todos os serviços com texto de sinalização apresentado no veículo, que pode ser utilizado para distinguir entre viagens numa rota. <br/><br/>Se a sinalização mudar durante uma viagem, os valores de `trip_headsign` podem ser substituídos definindo valores em `stop_times.stop_headsign` para `stop_times` específicos ao longo viagem. |
| `pattern_id`    | ID    | Obrigatório | O `pattern_id` identifica a variante de serviço em que a viagem opera na linha. <br/><br/>Não faz parte do GTFS standart, mas é obrigatório para nós TML.                                                                                                                                                                                                                                                                                                              |


### O que esta validação faz (agrupado por pattern_id)

Garante consistência de `trip_headsign` por `pattern_id`: para um mesmo `pattern_id`, todas as viagens devem partilhar o mesmo texto de destino exibido no veículo. Aqui a regra inclui “presença”: ausência (campo nulo) e cadeia vazia contam como o mesmo valor lógico (`""`), mas misturar “vazio” com um texto concreto não — isso produz dois valores distintos e falha.

#### Passa

- Se, para esse `pattern_id`, existir no máximo um `trip_headsign` “efetivo” distinto, isto é: zero ou um valor entre: ausência, string vazia (ambos `""`) e, no máximo, uma cadeia não vazia partilhada por todas as viagens. Na prática: ou todas têm o mesmo texto, ou todas estão vazias/ausentes (só a chave `""`).
- Falha se existirem dois ou mais valores distintos: por exemplo, uma viagem com headsign e outra sem, ou duas cadeias não vazias diferentes.

Diferença em relação a `route_id` / `shape_id` / `direction_id` (agrupados): nesses, viagens com o campo não preenchido em geral não entram no conjunto de “variedade”. Aqui, cada viagem contribui: ausência/empty é um valor, por isso “metade vazio e metade preenchido” no mesmo `pattern_id` falha.
