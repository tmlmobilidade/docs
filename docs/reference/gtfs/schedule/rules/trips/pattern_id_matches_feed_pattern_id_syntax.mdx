## Regras de validação do campo pattern_id


### Campos que serão utilizados nesta regra

| Nome do Campo | Tipo | Presença    | Descrição                                                                                                                                                 |
| ------------- | ---- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pattern_id`  | ID   | Obrigatório | O `pattern_id` identifica a variante de serviço em que a viagem opera na linha. <br/><br/>Não faz parte do GTFS standart, mas é obrigatório para nós TML. |


### Que formato é validado

Valida o formato do `pattern_id` em cada linha de `trips.txt` em que o campo vem preenchido: o valor tem de respeitar um padrão fixo de segmentos separados por `_` (não é validação de existência em `patterns` aqui, só o “shape” do texto — o ficheiro descreve o tipo como chave para `patterns.pattern_id`).

- Primeiro segmento: 1 a 4 caracteres, nenhum deles pode ser `_`.
- Segundo segmento:  exatamente 1 caracter que não seja `_`.
- Terceiro segmento: exatamente 1 caracter que não seja `_`.

Cada segmento deve ser separado por `_` por isso que não é permitido que algum dos segmentos contenha `_` como caractere.

O comentário do ficheiro fala de algo na linha de `"X" … "XXXX_X_X"`: o segmento inicial corresponde a 1–4 “letras/identificadores” sem `_`, seguido de `_<um carater>_<um carater>` (ex.: `a_b_c`, `L12_0_1`).

Comportamento

- Passa (sem fazer nada) se `pattern_id` for nulo — o campo continua opcional a nível de presença.
- Passa se o valor, quando existe, corresponde à expressão regular acima.
- Falha se `pattern_id` estiver preenchido mas não corresponder ao formato (a mensagem inclui o valor inválido, chave `pattern_id_format_validation.invalid`).

Resumo: é uma validação por viagem/linha, não por grupo; exige, quando o ID está presente, o formato canónico com dois separadores e comprimento do primeiro bloco entre 1 e 4 carateres sem `_`.
