## Regras de validação do campo drop_off_type


### Campos que serão validados nesta regra

| Nome do Campo                  | Tipo    | Presença                     | Descrição                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------ | ------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `drop_off_type`                | Enum    | Proibido Condicionalmente    | Indica o método de entrega.<br/>**Opções válidas:**<ul><li>`0` ou `vazio` - Entrega agendada regularmente.</li><li>`1` - Sem entrega disponível.</li><li>`2` - É necessário ligar para a agência para agendar a entrega.</li><li>`3` - É necessário coordenar com o motorista para agendar a entrega.</li></ul>**Proibido Condicionalmente**:<ul><li>`0` **proibido** se `start_pickup_drop_off_window` ou `end_pickup_drop_off_window` estiverem definidos.</li><li>Opcional caso contrário.</li></ul>                                          |
| `start_pickup_drop_off_window` | Horário | Condicionalmente Obrigatório | Horário em que o serviço on-demand fica disponível num local GeoJSON, grupo de locais ou paragem. <br/><br/>**Condicionalmente Obrigatório**:<ul><li>Obrigatório se `stop_times.location_group_id` ou `stop_times.location_id` estiver definido.</li><li>Obrigatório se `stop_times.location_group_id` ou `stop_times.location_id` estiver definido.</li><li>Obrigatório se `end_pickup_drop_off_window` estiver definido.</li><li>Proibido se `arrival_time` ou `departure_time` estiver definido.</li><li>Opcional caso contrário.</li></ul> |
| `end_pickup_drop_off_window`   | Horário | Condicionalmente Obrigatório | Horário em que o serviço on-demand termina num local GeoJSON, grupo de locais ou paragem. <br/><br/>**Condicionalmente Obrigatório**:<ul><li>Obrigatório se `stop_times.location_group_id` ou `stop_times.location_id` estiver definido.</li><li>Obrigatório se `start_pickup_drop_off_window` estiver definido.</li><li>Proibido se `arrival_time` ou `departure_time` estiver definido.</li><li>Opcional caso contrário.</li></ul>                                                                                                             |




### O que esta validação faz 

O campo `drop_off_type` em `stop_times.txt` indica como é feita a descida do veículo nesta paragem: horário normal, 
sem descida, com reserva por telefone ou coordenação com motorista. No GTFS usa uma enumeração (0 a 3); 0 ou vazio equivalente a descida regular). Com janelas de pickup/drop-off na mesma linha, o valor 0 ("descida regular") é proibido - o modelo de janelas que entre em conflito com "paragem fixa programada" neste sentido.

O campo `drop_off_type`no ficheiro `stop_times.txt` indica como será realizada a descida do veículo nesta paragem. No GTFS usa uma enumeração (0 a 3); 0 ou vazio equivalente a descida regular). Com janelas de pickup/drop-off na mesma linha, o valor 0 ("descida regular") é proibido - o modelo de janelas que entre em conflito com "paragem fixa programada" neste sentido.GTFS 

---

### Passa

- Valor entre 0 e 3 (enumerado válido).
- Com janelas definidas: tipo de descida não é 0 (ou o campo vazio, que o GTFS trata como regular mas aqui a verificação explícita só falha quando o valor é 0 com janelas - campo ausente não passa pelo ramo `dt == 0`).
- Código admitido pelo conjunto de opções do projecto, ou regra que aceita todas as opções.
- Campo vazio com regra em ignorar ou proibido (no sentido de saltar a verificação de presença) - sem mensagem por ausência.

---

### Falha

- Inválido - número fora de 0–3.
- Proibido com janelas - existe janela de pickup/drop-off preenchida e o tipo de descida é 0 (descida regular programada).
- Fora do permitido - valor GTFS válido mas não autorizado pelas opções do projecto.
- Ausência de valor quando a severidade não é “ignorar” e o projecto exige obrigatório ou recomendado (mensagem conforme política).
